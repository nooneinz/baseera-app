### وثيقة الهيكل التقني - منصة بصيرة التنفيذية

#### 1. مقدمة تنفيذية
تحدد هذه الوثيقة البنية التحتية والتقنية الفعلية لمنصة "بصيرة"، لضمان تكامل بيانات المبيعات، معالجة الاستعلامات الفورية، وتقديم المؤشرات الحيوية لصناع القرار بأعلى كفاءة وأقل زمن استجابة.

#### 2. أربع خدمات مستقلة خلف بوابة موحّدة (لا 3-Tier كلاسيكية)
البنية الفعلية ليست ثلاثية الطبقات بمعنى تقليدي، بل أربع خدمات مبنية بأطر مختلفة تعمل خلف `nginx` كموجّه وحيد حسب المسار:

| الخدمة | التقنيات المستخدمة | الوظيفة الرئيسية |
| :--- | :--- | :--- |
| **backend** (`/api/`) | ASP.NET Core (C#)، EF Core، PostgreSQL | B2B Admin API ولوحات الجوال، مع عزل متعدد المستأجرين (Multi-tenant) على مستوى الكيانات. |
| **dashboard** (`/dashboard/`) | Django، google-genai (Gemini) | القلب الفعلي للمنتج: وكيل الذكاء الاصطناعي (ReAct)، التحليلات المالية، ولوحة التحكم الرئيسية. |
| **mobile / web** (`/`) | Flutter | تطبيق الجوال وواجهة الويب البديلة. |
| **sandbox** (داخلي فقط) | FastAPI، subprocess | تنفيذ كود بايثون قصير يطلبه الوكيل الذكي، كعملية معزولة عن التطبيق الرئيسي. |

طبقة التخزين مشتركة بين الخدمات: **PostgreSQL** (البيانات الدائمة)، **Redis** (الكاش)، **MinIO** (الملفات)، جميعها محصورة داخل شبكة Docker خاصة (`internal: true`) بلا اتصال إنترنت خارجي مباشر.

#### 3. معايير الأمان وحماية البيانات
- TLS إجباري عند الحافة (nginx) مع HSTS، `X-Frame-Options: DENY`، و`nosniff`.
- تحديد معدل الطلبات: ١٠ طلبات/ثانية عند nginx، و١٠٠ طلب/دقيقة لكل مستخدم على مستوى الـ API.
- عزل متعدد المستأجرين في `backend` عبر `ITenantService` لكل كيان.
- قيد صلاحيات صارم على وكيل الذكاء الاصطناعي: أي إجراء يمس رقمًا ماليًا أو مقياس قرار (تحديث مقياس، حل مخاطرة، إغلاق هدر) ليس له استدعاء دالة تلقائي إطلاقًا — يظهر فقط كزر يوافق عليه إنسان.
- تنفيذ الكود الذي يطلبه الوكيل الذكي يمر عبر نقطة معزولة (`sandbox_client.py`): حاوية منفصلة بلا شبكة خارجية ولا أسرار عند توفرها، أو تنفيذ محلي مقيّد (بدون `open`/`__import__`/`eval`) كبديل مع مهلة زمنية صريحة.

#### 4. الفجوة المعمارية المفتوحة
لا توجد بوابة API موحّدة تجمع منطق العمل بين `backend` (C#) و`dashboard` (Python) — التوجيه الحالي عبر مسارات nginx فقط. هذا قرار معماري يستحق مراجعة مستقبلية عند نمو التكامل بين الخدمتين.
