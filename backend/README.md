# backend/ — ASP.NET Core API

## النطاق (محدَّث بعد قرار صريح — راجع الأرشيف قبل ما تفترض غيره)

كان هذا المجلد سكافولد كامل بلا نشر فعلي (commit واحد، بلا Dockerfile، بلا
migrations، `MobileDashboardController` يرجّع بيانات وهمية بالكامل، ومفتاح
API كان مكتوبًا صراحة بالكود المصدري). تم تفعيله وفتحه للنشر الحقيقي بتاريخ
٢٠٢٦-٠٩-٠٢ بناءً على قرار معماري صريح:

- **`backend/` (هذا المشروع) هو المرجع الوحيد لبيانات الاشتراكات والفواتير**
  (`Business`, `Subscription`, `Invoice`) بمجرد ربط بوابة دفع حقيقية
  (Thawani — راجع `Invoice.ThawaniTransactionId`). هذا لسه ما اكتمل: لا
  توجد migrations مولّدة فعليًا (تحتاج `dotnet ef migrations add
  InitialCreate` بجهاز فيه .NET SDK)، ولا يوجد اتصال حقيقي ببوابة الدفع
  بعد — `dashboard/views.py`'s `process_payment` بـDjango لسه المسار
  المستخدم فعليًا (محاكاة/يدوي، مو بوابة حقيقية) لحين اكتمال هذا الانتقال.
- **`dashboard/` (Django) يبقى صاحب لوحة التحكم والتفاعل** (AI agent،
  التحليلات، عرض قيم الاشتراك للمستخدم) — لكنه ينتقل تدريجيًا من كونه
  *مالك* بيانات الفوترة (`dashboard/models.py`'s `Invoice` الحالي) إلى
  كونه *قارئ* لها من هذا الـ backend، مو كاتبها.
- **قاعدة بيانات مستقلة تمامًا** (`baseera-backend-db` في `render.yaml`) —
  عزل حقيقي عن قاعدة Django، مو مجرد جداول منفصلة بنفس القاعدة. هذا قرار
  متعمد رغم أنه أبطأ بالبداية (يحتاج خطة مزامنة/ترحيل بيانات لاحقًا).
- تطبيق الجوال (`baseera_mobile_app/`) **مجمَّد حاليًا** — لا تُبنى عليه أي
  خطة نشر إلى أن يُستأنف العمل عليه. `MobileDashboardController` يبقى
  بياناته وهمية عمدًا لنفس السبب (لا يوجد كيان مبيعات/طلبات بالنموذج
  الحالي لِيُربط بشيء حقيقي).

## ليش هذا التوثيق موجود أصلاً

لأن أول نسخة من هذا المجلد اتبنت بجلسة وحدة وتُركت بلا أي إشارة لنيتها —
النتيجة: بعد أسبوع، `backend/` بدا وكأنه محاولة مهجورة تكرر ما يفعله Django
فعلًا (وفعلاً كان كذلك وقتها). لا تكرر هذا: أي تغيير بنطاق هذا المجلد
(خصوصًا حول ملكية بيانات الفوترة) يُحدَّث بهذا الملف فورًا، مو يُترك ضمنيًا
بالكود فقط.

## الحالة التقنية الحالية

| الجزء | الحالة |
|---|---|
| Dockerfile | جاهز (`backend/Dockerfile`) — build/publish متعدد المراحل |
| النشر على Render | مُعرَّف بـ`render.yaml` (`baseera-backend` + `baseera-backend-db`)، يحتاج ربط الخدمة فعليًا من لوحة Render |
| EF Core Migrations | **غير موجودة بعد** — لازم `dotnet ef migrations add InitialCreate` بجهاز فيه .NET SDK (غير متوفر ببيئة هذه الجلسة) |
| مصادقة `MobileDashboardController` | مفتاح API عبر متغير بيئة `TeamApiKey` (بعد ما كان مكتوبًا بالكود) — يفشل بأمان (500) لو غير مُعرَّف |
| بوابة الدفع الحقيقية (Thawani) | غير مربوطة بعد |
| انتقال Django عن ملكية `Invoice`/`PaymentIdempotency` | لم يبدأ — يحتاج خطة ترحيل منفصلة قبل أي قطع فعلي |
